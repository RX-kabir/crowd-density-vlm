# Experiment design

## Task and data
- **Test set:** 1,600 images from the JHU-CROWD++ test split. Ground truth per image: the people count (`total_count`, range 0–9,059, median 117.5) and a three-class crowd density (`crowd_density`: 0 = Low, 1 = Medium, 2 = High; 222 / 315 / 1,063 images = 13.9% / 19.7% / 66.4%). Both are in [`data/test_labels.csv`](../data/test_labels.csv).
- **Majority-class baseline:** always predicting "High" gives 66.44% density accuracy.
- **YOLO baseline:** a YOLO detector run on the same images; its count is the number of detected boxes (confidence 0.25). MAE 241.87, RMSE 737.65, MAPE 50.64%. See [`yolo/README.md`](../yolo/README.md) for a known issue with this count.

## The six conditions (per model)
| | Experiment A | Experiment B |
|---|---|---|
| 5-shot | five labelled support examples, then the test image | same, plus "YOLO predicted count: N" for the test image |
| Zero-shot | test image only, bare density labels | same, plus the YOLO line |
| Zero-shot + density definition | test image only; Low / Medium / High defined visually | same, plus the YOLO line |

- **Support examples (5-shot):** each support example is a training image with its true count and density label, shown as a user turn (image) followed by an assistant turn ("Ground Truth / Count / Density"). The five examples for every test image are fixed in [`support_mapping/support_mapping.csv`](../support_mapping/support_mapping.csv) and are identical for all models. The YOLO line is added only to the test turn, never to the support examples.
- **Prompt text:** [`prompts/`](../prompts/) (generated by `scripts/extract_prompts.py`). The wording is identical across models; only the message layout (API format) differs.
- **Required output format:** `Count: <integer>` and `Density: <0/1/2>`.

## Common settings
- **Images** are resized so that the longest side is at most 512 px (`thumbnail((512, 512))`) for every model.
- **Parsing:** `Count\s*[:=]\s*(\d+)` (counts with more than five digits are rejected as degenerate) and `Density\s*[:=]\s*([012])`, falling back to the words low / medium / high. Unparseable responses are excluded from the metric they affect and reported as "valid counts" / "valid density".
- **Open-source models** (Qwen2.5-VL-3B, LLaVA-Interleave-0.5B, Gemma 3 4B): greedy decoding, one run.
- **GPT-6.1 Terra:** OpenAI Responses API, reasoning effort `medium`, `max_output_tokens` 25,000 (includes reasoning), `store=False`, image `detail="high"`, no `temperature` / `top_p` (not allowed with reasoning) — so runs are **not deterministic** and each condition was run once. Full runs use the Batch API (50% cheaper); each condition was first piloted on 25 images synchronously (`*_Pilot.ipynb`).

## Metrics
- **Counting:** MAE, RMSE, MAPE (true count > 0), on rows with a parseable count; plus density-stratified error and signed bias, Pearson / Spearman correlation, worst cases.
- **Density:** accuracy, weighted precision / recall / F1, per-class recall, confusion matrix; binomial test against the always-"High" baseline.
- **Comparisons between conditions** (paired, per image): Wilcoxon signed-rank and paired t-test on absolute error; McNemar's exact test on density correctness. For Experiment B: how often the answer exactly equals the YOLO count ("echo" / substitution rate).

## Where things are
Per-condition folders hold the notebooks, the raw and evaluated CSVs, the figures and the findings documents (`<model>/<Five_Shot | Zero_Shot | Zero_Shot_Density>/`). `scripts/summarize_results.py` rebuilds the headline table from the evaluated CSVs.
